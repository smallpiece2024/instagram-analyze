# design-lab

instagram-analyze の分析画面のデザインシステムを選ぶための、使い捨ての比較ツール（R2.5 画面設計）。
アプリ本体（`apps/web`）からは独立しており、ビルド不要でブラウザだけで動く。

**数字と文言はすべて架空**。アカウント名「こまち焙煎所（架空）」も実在しない。実データ、実在のユーザー名、本番の URL は入れていない。

## 使い方

1. `doc/design-lab/v1/index.html` をブラウザで開く（ダブルクリックで可）
2. 上部のセレクトボックス、または数字キー（1〜9, 0）と ← → で案を切り替える
3. 「並べて見る」でモバイル幅（390px）と PC 幅（1024 / 1280px）を同時に、「10 案一覧」で全案をサムネイルで比較する（一覧はモバイル幅か PC 縮小を選べる）
4. 「画面」で 7 つの見本画面を切り替える
5. 「新しいタブで開く」で見本画面を単体で見る（URL 末尾の `#03` などで案を指定できる）

Google Fonts を読み込むため、インターネット接続が必要。グラフは `color-mix()` を使うので、2023 年以降のブラウザで見る。

## 構成

```text
doc/design-lab/
├─ README.md               この文書
└─ v1/                     第 1 ラウンド（10 案）
   ├─ index.html           切り替え・並列表示・一覧のコントローラ
   ├─ lab.css              見本画面の共通スタイル（レイアウトとアプリの枠）。トークン以外の値を直書きしない
   ├─ parts.css            部品（カード、数字タイル、タグ、表、グラフの枠、注記、状態）
   ├─ data.js              架空データ（投稿 24 件、日次指標 30 日、ストーリーズ 3 日、曜日×時間帯、リールのカットと文字、ジョブの記録）
   ├─ render.js            データから画面を描く。グラフはインライン SVG（ライブラリなし）
   ├─ variants.js          10 案の一覧（id、名前、方向性、トークン CSS のファイル名、グラフの 4 色、面の色）
   ├─ tokens/tokens-01.css … tokens-10.css   案ごとのデザイントークン（CSS custom properties）
   └─ screens/             見本画面。1 画面 1 ファイル。共通の head で lab.css／parts.css／data.js／render.js を読む
      ├─ overview.html     概要（主要指標と前期間比、日次推移、ファネル、投稿の種類の内訳）
      ├─ media-list.html   投稿一覧（サムネイル、種類、投稿日時、指標、並べ替え・絞り込みの UI）
      ├─ media-detail.html 投稿詳細（伸び方 1h〜7d と中央値・四分位、同種投稿との比較、カットと文字のタイムライン）
      ├─ reels.html        リール分析（長さ×視聴維持率の散布、長さの区分、画面変化の回数の分布、冒頭 3 秒の文字の有無）
      ├─ stories.html      ストーリーズ（1 枚ごとの閲覧数、操作の内訳、1 枚ごとの表、日ごとの要約）
      ├─ timing.html       投稿時刻（曜日×時間帯のヒートマップ、時間帯別の初速、上位の組み合わせ）
      └─ connection.html   接続と収集ログ（接続状態、トークンの期限、スケジュール、ジョブの実行記録と失敗の目立たせ方）
```

見た目の差は、すべて `tokens/tokens-XX.css` のカスタムプロパティで表現している。`lab.css` と `parts.css` は固定で、トークンを差し替えるだけで 10 案が切り替わる。本番（R3）では採用案の `:root` を `apps/web` のグローバル CSS のトークン定義に移す。

### トークンの区分

| 区分 | 主なプロパティ |
|---|---|
| 配色 | `--color-bg`、`--color-surface`、`--color-text`、`--color-text-muted`、`--color-border`、`--color-primary`、`--color-nav-*` |
| 増減と状態 | 増減は `--color-pos` / `--color-neg` / `--color-neutral`、状態は `--color-ok` / `--color-warn` / `--color-bad`（系列には使い回さない） |
| グラフ | `--chart-1`〜`--chart-4`（フィード、カルーセル、リール、ストーリーズの順で固定）、`--chart-grid`、`--chart-axis`、`--chart-ref`（中央値の破線）、`--heat`（ヒートマップと順序尺度の 1 色） |
| 文字 | `--font-body`、`--font-heading`、`--font-num`、`--font-size-*`、`--font-weight-*`、`--line-height`、`--letter-spacing-heading`、`--num-variant` |
| 形と間隔 | `--radius*`、`--shadow*`、`--space`、`--card-pad`、`--gap`、`--row-pad`、`--content-max` |
| 罫線と装飾 | `--bg-texture`、`--card-border`、`--nav-border`、`--nav-active-decor`、`--heading-decor`、`--tile-accent`、`--table-rule`、`--table-stripe`、`--tag-border`、`--header-bg` |

## グラフの決まり（dataviz スキルの要点）

- 先に形を決める。大きさ → 棒、推移 → 折れ線、割合 → 100% 積み上げ、1 つの値 → 数字タイル、時間帯×曜日 → ヒートマップ、カットのタイミング → タイムライン
- 系列の色は固定の順番（フィード、カルーセル、リール、ストーリーズ）。絞り込みで系列が減っても塗り替えない
- 軸は 1 本（2 軸グラフを作らない）。順序尺度は 1 色の濃淡（`--heat`）、正負は 2 色＋中立のグレー。虹色を使わない
- 棒は細め、データ端は 4px の角丸、線は 2px、点は 8px 以上、積み上げの区切りに 2px の面の色の隙間。系列が 2 つ以上なら凡例、4 系列までは直接ラベルも添える
- 文字は本文の色で書く（系列の色で文字を塗らない）。状態の色（良い／注意／重大）は系列に使わない
- 件数が少ない区分は薄く表示し、件数（n）を必ず添える

WARN の扱い（見本画面で守っていること）:

- 面とのコントラストが 3:1 未満の色（黄系と、案 01 の緑）は、数値ラベルか表を添える条件で使う。見本では種類の内訳に割合のラベルと表、投稿一覧にタグの文字を添えている
- CVD の隣接差が 6〜8 の帯（案 07、案 10）は、直接ラベル・隙間・テクスチャのどれかを添える条件で使う。見本では 100% 積み上げに 2px の隙間と割合のラベル、凡例に文字を添えている
- 第 2 ラウンドで案 07 か案 10 を土台にするなら、3 色目（リール）の黄を少し暗くして隣接差を 8 以上にする余地がある

## R2.5 の進め方

1. **第 1 ラウンド（この v1）**: 10 案を同じ見本画面で切り替えて比べ、気に入った案を 2〜3 つ選ぶ。画面構成への要望もここで出す
2. **選定**: 選んだ案の要素を組み合わせた案を `v2/` に 10 案ほど作り、もう一巡比べて 1 案に決める
3. **第 2 ラウンド後**: 採用した `tokens/tokens-XX.css` の `:root` を `doc/design-system.md` に確定値として書き出し、R3 で `apps/web` に移す。出た要望は `doc/requirements/requirements-definition.md` に反映し、追加のデータが必要なものは収集処理（R1／R2）に早めに加える

案を組み合わせたい場合は、トークンファイルを 1 つ複製して値を差し替え、`variants.js` に追加すれば 11 案目として比較できる。

## 見本画面の注記

- 時刻は日本時間。日次指標の日付だけは API の区切り（米国太平洋時間）で、概要と投稿時刻の画面にその注記を入れている（要件 5.5 章）
- 操作（並べ替え、絞り込み、期間の切り替え、ボタン）は見た目だけで動かない。第 1 ラウンドは見た目と画面構成の比較が目的
- 投稿詳細はリール（id 1）を見本にしている。フィードとカルーセルの詳細（投稿単位のファネル）は第 2 ラウンドで足す
- サムネイルは CSS のプレースホルダー。実画像は入れていない
